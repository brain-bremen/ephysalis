# Configuration reference

Generated by `python -m ephysalis.config_reference docs` from the code; do not edit. JSON Schema of session.toml for editors: `schema/session.schema.json`.

## conversion_batch.toml (schema version 5)

The file describes the whole pipeline from the recording session folders to the outputs: the software, the recording sessions, their configs, and every setting of every step. Example (paths are relative to `root`, which is relative to the file; default: the file's folder):

```toml
schema_version = 5
conversion_batch_name = "V1 array recordings of monkeys B and F"
root = ".."
work_dir = "derivatives/ephysalis/{recording_session}"
state_dir = "derivatives/ephysalis"            # pause file and status table (default: <root>/.ephysalis)
recording_session_root = "sourcedata"          # the folders are relative to it (default: root)
recording_session_config_file = "code/sessions/{recording_session}/session.toml"   # optional
recording_sessions_file = "code/sessions/recording_sessions.toml"   # optional: a (generated) list
recording_sessions = [                         # one recording session per line (after those of the file)
    { subject = "f", folder = "sub-f/ses-20091203", steps = { lfp = { rate_hz = 500.0 } } },
]

[source_cache]                                 # how the steps read the session folders (default: direct)
mode = "local"                                 # direct | local (a copy on a local disk)
dir = "/data/ephysalis-cache"                  # local: required
max_size_gb = 500                              # all copies together (optional)
reserve_gb = 10                                # left free on the disk (default 10)

[software]                                     # minimum versions; newer ones run the file too
ephysalis = "0.3.0"
ephysalis-bremen = "0.2.0"                     # every package of a plugin the sessions use

[defaults]                                     # session.toml content of every recording session
lab = "Kreiter lab"

[subject_defaults.b]                           # session.toml content of the recording sessions of subject b
input_format = "mcd"                           # the plugins: required (no detection in a batch)
metadata_plugin = "vstim"
experimenter = ["I. G."]
[subject_defaults.b.aux_channels.digital]
trial_start = { bit = 0, description = "trial start" }

[steps.lfp]                                    # the steps that run; every setting is required
probes = []
rate_hz = 1000.0
max_denominator = 10000
anti_alias_kaiser_beta = 5.0
anti_alias_half_length = 10
anti_alias_cutoff = 1.0
n_jobs = 4

[steps.export]
output_format = "dh5"
session_label = "{session_label}"
# ... (all settings of the step)

[sessions."sub-b/ses-20101209"]                # decisions about single sessions of the lists
include = false                                # e.g. recording broken after 10 min
```

A batch file can build on another one: `extends = "pipeline.toml"` (relative to the file) reads that file first; the tables of this one are merged into it key by key, its values (also `recording_sessions`) replace the base's (`recording_sessions_file = ""`: none). E.g. a trial run on a few days with its own work dir and BIDS root. Decisions in `[sessions]` of the base apply only to the sessions this file lists as well.

The recording sessions are those of `recording_sessions_file` (a TOML file with `recording_sessions = [...]`, e.g. generated from an inventory) and of `recording_sessions`. Each entry: `subject` (the session's `subject_id`) and `folder` (below `recording_session_root`), optionally `include` (false: listed but not run), `recording_session_config_file` (instead of the template), `session_config` (session.toml content, after the file) and `steps` (settings of this session that differ from `[steps]`); `[sessions."<folder>"]` adds or replaces these optional keys of a listed session (so that a generated list stays as it is). The id of a recording session is its folder with `/` as `_` (`sub-b_ses-20101207`); it names its work dir, its row in the status table and its `--recording-sessions` selection. Placeholders in `work_dir`, `recording_session_config_file` and step settings: `{recording_session}` = the id, `{subject}` = the subject, `{session_label}` = the last folder name without `ses-`.

The steps that run are the `[steps.<step>]` tables, in the order of the pipeline; each lists every setting of its step (see the configuration reference: `ephysalis.step_settings`). Every recording session's config names its `input_format` and `metadata_plugin`, and `[software]` lists ephysalis and the package of every plugin used with the version the file was made for; `ephysalis run` refuses older installed versions. Newer versions read the file: a format change comes with a migration (`CONVERSION_BATCH_MIGRATIONS`).

`[source_cache]` (`ephysalis.conversion_batch.source_cache`): `local` copies each session's folder once before its first step that has to run and let the steps read the copy (deleted when the session ends), and prefetches the next sessions while others compute; the copies together stay below `max_size_gb` and leave `reserve_gb` free, a session waits for space and one that alone is too big is read directly. It changes only where the data are read from (provenance records the original folder), not the results; `ephysalis run --source-cache` overrides it for one run.

A recording session's config is `[defaults]`, overridden by `[subject_defaults.<subject>]`, by its `recording_session_config_file` (if the template is given, the file must exist) and by its `session_config`: tables are merged key by key, everything else (values, arrays such as `runs`) is replaced. Every part must have the current `schema_version` (or none). Relative probe geometry files are relative to the file that names them (the defaults and `session_config`: the conversion batch file).

## Step settings (`[steps.<step>]` of conversion_batch.toml)

In a conversion batch every setting of a step that runs is required; on the command line they are the step's options (`ephysalis lfp --rate-hz 1000`, booleans as `--x` / `--no-x`), with these defaults.

### `[steps.align-clocks]`

| key | type | default | description |
|---|---|---|---|
| `cache_dir` | string | `""` | Sync edge cache (empty: <work-dir>/sync) |

### `[steps.calibrate]`

No settings (an empty table runs the step).

### `[steps.extract-trials]`

No settings (an empty table runs the step).

### `[steps.extract-events]`

No settings (an empty table runs the step).

### `[steps.extract-behavior]`

No settings (an empty table runs the step).

### `[steps.lfp]`

LFP: the LF stream (or the wideband stream) resampled with the anti-alias filter.

| key | type | default | description |
|---|---|---|---|
| `rate_hz` | float | `1000.0` | Output sampling rate (Hz) |
| `max_denominator` | integer | `10000` | Largest denominator of the rational up/down ratio approximating rate_hz / input rate |
| `anti_alias_kaiser_beta` | float | `5.0` | Kaiser window beta of the anti-alias FIR |
| `anti_alias_half_length` | integer | `10` | Half length of the anti-alias FIR in output samples (10 * max(up, down) upsampled input samples); it reaches this far into the future and the past |
| `anti_alias_cutoff` | float | `1.0` | Cutoff of the anti-alias FIR as a fraction of the output Nyquist frequency |
| `probes` | list[string] | `[]` | Only these probes (empty: all) |
| `n_jobs` | integer | `4` | Parallel jobs |

### `[steps.quality]`

| key | type | default | description |
|---|---|---|---|
| `probes` | list[string] | `[]` | Only these probes (empty: all with [probes.<id>.quality]) |

### `[steps.csd]`

|---|---|---|---|

| `n_jobs` | integer | `4` | Parallel jobs |

### `[steps.mua]`

MUA envelope: the wideband signal high-pass filtered, rectified and resampled with the anti-alias filter.

| key | type | default | description |
|---|---|---|---|
| `rate_hz` | float | `1000.0` | Output sampling rate (Hz) |
| `max_denominator` | integer | `10000` | Largest denominator of the rational up/down ratio approximating rate_hz / input rate |
| `anti_alias_kaiser_beta` | float | `5.0` | Kaiser window beta of the anti-alias FIR |
| `anti_alias_half_length` | integer | `10` | Half length of the anti-alias FIR in output samples (10 * max(up, down) upsampled input samples); it reaches this far into the future and the past |
| `anti_alias_cutoff` | float | `1.0` | Cutoff of the anti-alias FIR as a fraction of the output Nyquist frequency |
| `probes` | list[string] | `[]` | Only these probes (empty: all) |
| `highpass_hz` | float | `300.0` | High-pass cutoff (Hz) |
| `highpass_order` | integer | `4` | Order of the high-pass filter |
| `highpass_type` | "butter" / "bessel" / "cheby1" / "cheby2" / "ellip" | `"butter"` | IIR design of the high-pass (scipy.signal.iirfilter ftype) |

## session.toml (schema version 10)

Per recording session; in a conversion batch the `[defaults]`, the session's file and its `session_config` are merged (tables key by key). A file without `schema_version` is taken as the current version; other versions are not read.

### top level

| key | type | default | description |
|---|---|---|---|
| `schema_version` | integer | `10` | Version of this format; only the current one is read |
| `session_id` | string | required | Id of the recording session (NWB session_id; in a conversion batch: from its folder) |
| `subject_id` | string | required | Id of the subject (NWB / BIDS subject) |
| `input_format` | string | none | Input format plugin, e.g. spikeglx, openephys, mcd, daq; detected from the files if not set (required in a conversion batch) |
| `metadata_plugin` | string | none | Metadata plugin of the runs that do not name their own, e.g. vstim; 'none': no plugin; detected per run if not set (required in a conversion batch) |
| `experimenter` | list[string] | `[]` | Names of the experimenters (NWB) |
| `lab` | string | none | Lab (NWB) |
| `institution` | string | none | Institution (NWB) |
| `description` | string | `""` | Description of the session (NWB session_description) |
| `task` | string | none | Task (BIDS task entity, e.g. shapetracking); runs can have their own |
| `probes` | table: name -> ProbeConfig | `{}` | Probes by id (e.g. imec0, v1) |
| `notes` | string | `""` | Free text |

### `[probes.<name>.csd]`

Compute the CSD of this probe (ephysalis csd); needs the probe geometry. Current source density of a 2-D electrode array (Borisov's `dh_csd` V3.1 [RBF], `ephysalis.processing.csd`): Gaussian RBF interpolation of the LFP through the input electrodes, CSD = -Laplacian / specific resistance at the output electrodes. Defaults: the lab's parameters for the Fritz array.

| key | type | default | description |
|---|---|---|---|
| `grid_spacing_m` | float | `0.003` | Array grid spacing (m); the RBF width is grid_spacing_m x rbf_parameter |
| `rbf_parameter` | float | `2.2758` | RBF interpolation parameter (dh_csd 'rbfparam') |
| `specific_resistance_ohm_m` | float | `1.0` | Specific resistance of the tissue (Ohm m) |
| `exclude_inputs` | list[string] | `[]` | Channel ids not used as inputs (e.g. a bad electrode); channels without calibration are left out as well. Outputs: all channels of the probe |

### `[probes.<name>.quality]`

Select the good channels of this probe (ephysalis quality); needs the probe geometry. Channel selection on the LFP of each run (`ephysalis quality`, `ephysalis.processing.quality`; port of the Fritz/Mini BIDS conversions). The CSD then uses the good channels only. Defaults: their criteria.

| key | type | default | description |
|---|---|---|---|
| `neighbour_radius_um` | float | `3100.0` | Neighbours of a channel: contacts within this distance (Fritz epidural array 3100, intracortical arrays 2100) |
| `clip_counts` | integer | `32000` | \|LFP\| >= this (counts) is clipping |
| `max_clip_fraction` | float | `0.1` | Bad if clipping in this fraction of the windows |
| `max_abs_power_z` | float | `3.0` | Bad if the robust z of the 2-200 Hz power is beyond |
| `min_neighbour_correlation` | float | `0.3` | Bad if the 2-100 Hz correlation with the mean of the neighbours is below |
| `max_line_db` | float | `10.0` | Bad if the 50 Hz peak is this far above 40-60 Hz (dB) |
| `n_windows` | integer | `300` | Windows spread over the run |
| `window_s` | float | `2.0` | Window length (s) |
